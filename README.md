# senbi-auto

네이버 블로그 **자동 포스팅·발행·이웃관리** 데스크톱 앱. senbiPost의 Claude 생성·검증 파이프라인을 이식하고, 그 위에 Playwright 브라우저 자동화(발행·이웃)를 얹었다. 맥·윈도우 공용. **Electron 앱**(더블클릭 실행 + 트레이 상주)이며, 내부 엔진은 브라우저 없이 백그라운드에서 도는 Node 데몬이다 — 대시보드는 설정·모니터링용 조종석일 뿐.

## 무엇을 하나

1. **학습·생성** — 설정한 블로그의 최근 글 ~20개를 크롤링해 문체를 학습하고, 주제 키워드로 새 글을 생성한다. (상업어·비속어·필터 검증, 분량 보정, 모바일 줄바꿈, 센비·GEO 스코어까지 senbiPost와 동일)
2. **이미지** — 크롤한 글의 이미지를 가져와 **약한 필터**(밝기·채도·색상 미세 보정 + 가장자리 크롭 + 재인코딩)를 씌워 삽입한다. 부족하면 내 이미지 폴더(`~/.senbi-auto/my-images`)에서 보충.
3. **발행** — 로그인 세션으로 SmartEditor에 글을 채워 발행(또는 임시저장).
4. **이웃관리** — 이웃 새글에 공감 + 맥락형 AI 댓글(랜덤 지연·일일 한도·중복 방지), 주제 키워드로 블로그를 찾아 서로이웃 신청(AI 문구).

### 오류 알림

글 발행이나 이웃 관리가 오류로 중지되면 **대시보드 상단에 빨간 배너**가 뜨고, 앱을 쓰는 중이면 **데스크톱 알림**(맥 알림센터 / 윈도우 알림)도 함께 뜬다. 알림에는 무슨 작업이 어떤 이유로 멈췄는지가 그대로 적힌다. 확인을 누르면 사라지고, 누르기 전까지는 앱을 껐다 켜도 남아 있다.

알림은 파일에 남으므로, 작업을 걸어 두고 자리를 비웠다가 돌아와도 무엇이 왜 멈췄는지 확인할 수 있다.

### 윈도우 환경 대응

설치본이 윈도우 PC에서 걸리기 쉬운 지점들을 앱이 스스로 처리한다.

| 상황 | 앱의 대응 |
| --- | --- |
| Chromium 이 없음 (설치 직후) | 자동으로 내려받고 진행률 표시 |
| 방화벽이 `cdn.playwright.dev` 차단 | PC에 있는 **Edge / Chrome** 으로 대체 실행 |
| 3060 포트를 다른 프로그램이 사용 중 | 빈 포트를 찾아 이동, 대시보드 주소도 따라감 |
| 앱이 비정상 종료돼 엔진이 남음 | 종료 시 `taskkill` 로 프로세스 트리째 정리 |
| 백신·검색 인덱서가 설정 파일을 잠금 | 저장 재시도 후 직접 덮어쓰기로 폴백 |
| 이미지 모듈(sharp)이 격리·손상 | 시작할 때 검사해 알림 (글은 계속 발행) |
| 엔진이 시작 못 함 | 마지막 오류 내용을 그대로 대화상자에 표시 |
| 데스크톱 알림이 안 뜸 | AppUserModelID 지정으로 윈도우 토스트 정상화 |
| 트레이 아이콘이 안 보임 | 윈도우는 컬러 아이콘 사용 (맥은 단색 템플릿) |

### 계정별 프록시 (IP:포트)

이 PC의 IP로 로그인하자마자 블로그가 보호조치에 걸리는 경우, 계정마다 프록시를 적어 둔다. `상세 설정 → 블로그 계정 → 설정 → 프록시 (IP:포트)`.

- 적는 모양: `123.45.67.89:8080` · `123.45.67.89:8080:아이디:비밀번호` · `아이디:비밀번호@123.45.67.89:8080` (앞에 `socks5://` 도 가능)
- **로그인·세션 확인·발행·이웃 관리가 전부 그 IP로만 나간다.** 브라우저를 띄우기 전에 프록시로 실제 접속해 보고, 안 되면 **작업을 멈춘다** — 이 PC의 IP로 대신 접속하지 않는다. WebRTC 로 실제 IP가 새는 것도 막는다.
- **세션은 로그인한 IP에 묶인다.** 프록시를 새로 적거나 바꾸면 그 계정은 `재로그인 필요` 가 되고, 다시 로그인하기 전까지 작업하지 않는다. 다른 IP로 만든 세션을 새 IP로 들고 가면 그 자체가 'IP가 갑자기 바뀐 접속'으로 보이기 때문이다. 로그인 창도 그 프록시로 뜬다.
- `연결 확인` 을 누르면 네이버에 보일 IP와 이 PC의 IP를 함께 보여 준다. 둘이 같으면 그 프록시는 IP를 바꿔 주지 못하는 것이다.
- 같은 프록시인데 나가는 IP가 로그인 때와 달라지면(IP가 도는 프록시) 막지는 않고 작업 기록에 경고를 남긴다. 보호조치가 계속되면 IP가 고정되는 프록시를 쓴다.
- 학습 블로그 글을 받아 오는 크롤링(로그인 없음)은 프록시를 쓰지 않는다.

### 키워드 규칙 (발행 시 코드로 강제)

1. **학습 블로그에서 수집한 키워드만 쓴다.** AI가 새 주제를 지어내지 않는다. 후보는 학습한 글 제목에서 뽑은 키워드 풀(+템플릿 학습 시 수집된 키워드)뿐이다.
2. **최근 쓴 키워드와 겹치면 안 된다.** 표현만 바꾼 같은 소재(소재 어절 2개 이상 공유, 포함 관계, `렌탈↔대여↔임대`처럼 거래어만 바꾼 것)도 겹침으로 본다.

**키워드는 소재가 끊기지 않게 뽑는다.** 제목 `컨베이어 피자 오븐 렌탈 행사 현장 …`에서는 첫 거래어까지인 `컨베이어 피자 오븐 렌탈`이 키워드다(앞 2어절만 자른 `컨베이어 피자`가 아니다). `단 한달 사용에 구매하시겠어요?` 같은 문장형 제목에서는 키워드를 뽑지 않는다.

**같은 제품을 되풀이해 올리는 것이 이 앱의 목적이다.** 그래서 막는 것은 '너무 짧은 간격의 반복'뿐이다. 같은 키워드는 기본 **10일** 뒤에 다시 후보가 된다(한 달에 세 번). 공통 설정의 `같은 키워드 다시 쓰기까지 간격`으로 바꾼다.

- 간격은 **블로그마다 따로** 센다. 다른 블로그에 올린 제품을 이 블로그에서 못 쓰게 막지 않는다.
- 후보는 **올린 적 없는 제품 → 가장 오래전에 올린 제품** 순으로 나온다. 제품이 고르게 돌아가며 올라간다.
- 사진도 같다. 안 쓴 사진을 먼저 쓰고, 다 썼으면 가장 오래전에 쓴 사진부터 다시 쓴다.
- 자동발행을 끄고 만든 초안·유사문서로 발행이 보류된 초안의 키워드도 '쓴 것'으로 친다. 발행하다 오류로 실패한 글의 키워드는 바로 다시 쓸 수 있다.
- 주제가 같아도 **문장을 베끼는 것은 막는다.** 참고글과 겹치는 문장이 30%를 넘으면 다시 쓰고, 그래도 넘으면 발행하지 않는다.

두 규칙은 발행 직전 `assertKeywordAllowed`에서 다시 검사하고, 어기면 **발행하지 않고 중단**한다. 동작 확인:

**시작 전에 직접 고를 수도 있다.** `오늘 작업 시작` → 블로그를 고르면 **키워드 고르기** 화면이 뜬다. 여기에는

- 그 블로그가 **최근에 쓴 메인키워드**가 최신순으로 (어떤 소재를 이미 썼는지 한눈에)
- **학습 블로그에서 수집한 키워드** 중 아직 안 쓴 것들 (사진이 없는 소재는 `사진없음` 표시)
- 위 둘을 다 반영한 **추천 키워드**와 그 근거

가 함께 나온다. 글 수만큼 고르면 고른 순서대로 발행하고, 안 고르면 추천 키워드로 자동 진행한다. 화면에 보이는 후보·추천은 발행 잡과 **같은 코드**(`run/keywordPlan.ts`)로 계산하므로 실제로 쓰이는 것과 어긋나지 않는다. 직접 고른 키워드도 위 두 규칙 검사를 똑같이 통과해야 발행된다.

```bash
npm run verify:keywords              # 설정된 학습 블로그 기준
npm run verify:keywords -- <blogId>  # 특정 블로그로 확인
```

## 한 번 실행하면 일어나는 일

`오늘 작업 시작` → (계정이 여러 개면 블로그 고르기) → 키워드 고르기 → 작업 시작.

1. **로그인 확인** — 글을 만들기 전에 글쓰기 화면이 열리는지부터 본다. 세션이 만료됐으면 글을 만들지 않고 바로 알린다.
2. **학습** — 학습 블로그 글을 받아 온다. 키워드 고르기 화면에서 받은 것을 30분 동안 그대로 쓰므로 글마다 다시 받지 않는다.
3. **키워드 → 생성 → 이미지 → 발행** — 글 수만큼 반복. 발행 텀은 글이 실제로 올라갔을 때만 기다린다.
4. 실패한 이유가 다음 글에서도 똑같이 걸릴 것(키워드 없음·API 키 없음·세션 만료)이면 남은 글은 만들지 않는다.
5. **이웃 관리** — 켜 둔 계정만.

## 구조

```

  config/   paths·store(JSON)·settings          설정/영속
  core/     types·text·score·geoScore·activity·drafts·logger

  media/    images                              다운로드 + sharp 약한 필터   ✅검증
  generate/ pipeline·index·social               Claude 생성/검증 + 댓글·서로이웃 문구
  naver/    session·publish·neighbor            Playwright 세션·발행·이웃      ⚠️튜닝
  run/      postJob·neighborJob·keywordPlan     오케스트레이션 + 키워드 후보·추천

  server/   dashboard·public/index.html         Fastify + 로컬 대시보드      ✅검증

  scripts/  crawl-test·gen-test·img-test·login·browser-check
```

## 설치 (맥)

```bash
cd senbi-auto
npm install
npm run setup:browser        # Playwright Chromium 설치 (1회)
cp .env.example .env         # ANTHROPIC_API_KEY 채우기
```

## 사용

### 데스크톱 앱으로 실행 (권장)

```bash
npm run app          # Electron 앱 창 + 트레이 상주로 실행
```

앱 아이콘 더블클릭과 동일한 경험 — 자체 창으로 대시보드가 뜨고, 창을 닫아도 **상단 메뉴바(트레이)에서 백그라운드로 계속 실행**된다. 종료는 트레이 메뉴 → 종료.

설치용 `.dmg`(맥) / `.exe`(윈도우)를 만들려면:

```bash
npm run app:build    # release/ 에 설치 파일 생성 (electron-builder)
```

### 자동 업데이트

설치본은 GitHub Releases를 보고 스스로 업데이트한다. **윈도우는 사람 손 없이 끝까지 자동**이다 — 10분마다 확인해 백그라운드로 받고, 진행 중인 발행·이웃 작업이 없을 때 1분 카운트다운 뒤 스스로 재시작해 적용한다(작업 중이면 끝날 때까지 기다린다). 맥은 새 버전 알림 후 dmg를 받아 교체한다. 자세한 규칙과 배포 방법은 [RELEASE.md](RELEASE.md) 참고.

```bash
npm run ship   # 맥에서: 버전 올림 + 태그 푸시 → CI가 윈도우 exe 빌드·릴리스 → 윈도우 앱이 15분 안에 자동 적용
```

### 헤드리스 데몬으로만 실행 (창 없이)

```bash
npm start            # http://localhost:3060
```

### 최초 1회 · 단독 테스트

```bash
npm run login                            # 네이버 로그인 세션 만들기 (창에서 직접 로그인)
npm run crawl -- <blogId> 5              # 크롤만
npm run gen   -- <blogId> "<메인키워드>" # 크롤 → 생성 (API 키 필요)
```

대시보드에서 대상 블로그·주제 키워드·이미지 소스·이웃 한도를 설정하고, `오늘 작업 시작`을 누르면 선택한 계정으로 발행·이웃 관리가 진행된다. **예약 실행(cron)은 없다** — 앱을 켜고 버튼을 누를 때만 동작하므로, 자리를 비운 사이에 혼자 글이 올라가는 일은 없다.

## 현재 상태

- ✅ **크롤·이미지 필터·생성 파이프라인·대시보드**: 구현·검증 완료
- ✅ **네이버 발행·공감·댓글**(`naver/publish.ts`, `naver/neighbor.ts`): 실계정에서 검증(2026-07~08). 네이버가 화면 구조를 바꾸면 각 파일 상단 `SEL`의 셀렉터를 고쳐야 한다.
- ⚠️ **서로이웃 신청**: 구조는 완성. 실제 신청 기록이 아직 없어 첫 실행은 창을 띄워 놓고 확인할 것.

## 안전·정책

- 대시보드는 **이 PC에서만** 열린다(127.0.0.1). 다른 웹사이트가 보낸 요청과 localhost가 아닌 주소로 들어온 요청은 거부하므로, 앱을 켜 둔 채 다른 사이트를 열어도 그 사이트가 발행을 시작시킬 수 없다.
- 일일 공감·댓글·서로이웃 한도와 중복 방지는 **계정마다 따로** 센다.
- 프로그램은 **비밀번호를 대신 입력하지 않는다** — 첫 로그인만 사용자가 직접 하고 세션을 재사용한다.
- 자동 댓글·공감·대량 서로이웃은 네이버 운영정책상 **제재 위험**이 있다. 랜덤 지연·일일 한도·맥락형 댓글로 위험을 낮췄으나, 한도는 보수적으로 시작할 것. `autoPublish` 기본값은 꺼짐.
- 크롤 이미지 재사용은 저작권 이슈가 있을 수 있다 — 가능하면 내 이미지 폴더를 함께 쓰는 것을 권장.
